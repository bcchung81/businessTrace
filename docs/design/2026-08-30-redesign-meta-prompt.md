# 성과돋보기 전체 화면 재설계 — `/design` 메타 프롬프트

2026-08-30. Claude Code 의 `/design` 명령(Claude Design 캔버스)에 붙여 넣는 프롬프트다. 세 번에 나눠 실행한다 — **① 방향 → ② 홈 확정 → ③ 전 화면**. 매 실행은 같은 본문에 `[실행 N]` 블록만 바꿔 붙인다.

근거 문서: `docs/superpowers/plans/2026-08-26-nextjs-rearchitecture.md`(로드맵·Phase B 예정 화면) · `docs/superpowers/specs/2026-08-30-event-monitoring-design.md`(현행 화면의 원천) · `docs/superpowers/specs/2026-08-29-dashboard-redesign-design.md`(원칙·토큰 3단·Panel 문법 — 섹션 구성은 08-30 에 대체됨) · `docs/design/2026-08-29-microduck-design-analysis.md`(현행 시각 언어) · `docs/2026-08-28-consulting-brief.md`(독자·과제 근거). 인벤토리는 2026-08-30 코드에서 옮겼다 — 화면이 바뀌면 §4 를 함께 고친다.

## 실행 순서

| 실행 | 명령 | 받는 것 | 다음 실행 전 사람이 정하는 것 |
|---|---|---|---|
| ① 방향 | `/design` + 본문 + `[실행 1]` | 홈 화면 저해상 방향 시안 3안 + 워드마크 스케치 3안 | 방향 1개, 워드마크 1개 |
| ② 홈 확정 | `/design` + 본문 + `[실행 2]` (선택 결과 기입) | `/dashboard` 고해상 데스크톱·모바일·다크 + 상태 변형 | 세부 수정 |
| ③ 전 화면 | `/design` + 본문 + `[실행 3]` | 나머지 현행 4화면 + 예정 5화면 + 컴포넌트 시트 + 브랜드 보드 | 스펙으로 이관 |

`/design` 은 기본적으로 코드베이스의 토큰·컴포넌트를 픽셀 단위로 복제하려 한다. 그래서 본문 §5 에 "현행은 출발점이지 정답이 아니다"를 못 박았다. 실행 ① 은 **정적 목업**으로 요청한다 — 프로토타입은 스펙 확정 후다.

════════════════════════════════════════
§2 고정 원칙 — 위반하면 시안 탈락
════════════════════════════════════════
A. 3층 — 위=상태(지금 어떤가) / 중=변화(무엇이 바뀌었나) / 아래=상세(왜 그런가).
B. 색만으로 상태를 말하지 않는다 — 상태색은 항상 아이콘·빗금·점선·라벨과 함께.
C. 비교 기준 없는 숫자 금지 — 분모·비율·직전값·기준일 중 하나를 옆에 둔다.
D. 시그니처: **사업자번호 미확보는 빈칸이 아니라 경고.** 국세청·DART 와 대조할 수 없어 뉴스 외 근거가 없다.
   모든 화면에서 같은 경고 문법.
E. 빈칸은 네 종류 — 결측(원천에 없음) · 측정 불가(해당 없음) · 충돌(동명 타사) · 미조회(아직 안 봄).
   처방이 다르므로 서로 다르게 보인다.
F. 상태색은 제품 의미에만 — verified(검증 통과) · review(검토 필요) · risk(리스크) · pending(미분석).
   장식·강조·브랜드에 쓰지 않는다.
G. 숫자 열은 tabular-nums — 사업자번호·점수·날짜·인원이 세로로 정렬돼야 스캔된다.
H. 시선을 잡는 장치는 화면에 하나 — 지금은 리본이다. 표 위에 또 두지 않는다.
I. 심각도는 참고, 확인은 사람 — 경보라도 "미확인" 상태가 보이고, 확인 버튼이 판정보다 앞에 오지 않는다.
J. 이 시스템에 없는 것을 그리지 않는다 — 검색창·알림 벨·아바타·설정 메뉴·다중 팀은 없다.
K. 0건도 보인다 — 집계 항목은 0이면 "없음"으로 남긴다. 항목이 사라지면 점검했는지 알 수 없다.
L. 결측과 0을 구분한다 — 없는 데이터를 0으로 그리지 않는다. 표·차트의 결측 칸은 빗금 또는 "—".
M. 표와 숫자 열은 절대 기울이지 않는다 — 장식은 헤더·리본에서 끝난다. 강조색은 primary 하나.

지시:
 · (1)의 **상태색 의미 매핑과 3단 구조**는 유지한다. 색값 자체는 제안해도 된다(대비 AA 이상, 라이트·다크).
 · (2)는 **재평가 대상**이다. 방향 시안 3안 중 최소 1안은 코믹북 층을 걷어낸 절제형, 1안은 유지·정제형, 1안은 제3의 방향.
 · 픽셀 복제 금지 — 현행 컴포넌트 anatomy(필드·상태)는 지키되 형태는 새로 그린다.
 · 서체는 Pretendard 본문 유지. 디스플레이·모노는 제안 가능(Google Fonts 한정, 폴백 명시).

§6 브랜드·워드마크
════════════════════════════════════════
"성과돋보기"는 지금 헤더에 15px 볼드 텍스트로만 있어 메뉴와 구분되지 않는다.
 a. 돋보기 은유(대조·확대·검증)를 살린 한글 로고타입 — 한 글자·한 획에 렌즈·초점·대조선을 심는 정도로 절제. 심볼 단독형 동반.
    브랜드색은 primary 또는 label 단색. 상태색 금지.
 b. 적용 4곳: 헤더(56px 안, 태그라인 동반) · 로그인 H1 · 월간 문서 표지 · 파비콘 16/32. 각 최소 크기 명시.
 c. 명칭 후보 2~3개(띄어쓰기·조어·한자어/고유어 비율) — 각각 스케치 + 한 줄 근거. **시안 기본은 현행 명칭**, 후보는 브랜드 보드에만.
