# 사고 기록

같은 실수를 두 번 하지 않기 위한 로그다. **최신 항목이 위**에 온다.

이 파일은 컨텍스트에 로드되지 않는다. `CLAUDE.md` 에서 포인터로만 참조한다.

## 기록·승격 규칙

```
1회 발생  → 여기에 기록만 한다
2회 발생  → 규칙으로 승격한다
              정규식·명령으로 판정 가능 → .claude/settings.json 훅
              판단이 필요           → .claude/skills/ 스킬
CLAUDE.md → 코드 쓸 때 매번 필요한 것이 아니면 추가하지 않는다
```

한 번은 노이즈, 두 번이 패턴이다. 매 실수마다 규칙을 만들면 규칙 파일의 신호 대 잡음비가 무너진다.

항목 형식은 **증상 / 원인 / 발견 / 재발 방지** 네 줄이다. `재발 방지` 에 훅이나 스킬 링크가 없으면 그 항목은 아직 박제되지 않은 것이다.

**분리 트리거:** 이 파일이 500줄을 넘으면 연도별로 분할한다. 항목 하나가 40줄을 넘기면 그것만 별도 파일로 빼고 여기엔 요약 4줄 + 링크를 남긴다.

## 2026-09-01 · 나라장터 낙찰 12개월 스캔이 3번째 창부터 조용히 멈췄고 43개사가 "조달 미참여" 로 기록됐다

- **증상**: `scripts/collect-procurement.ts` 로 최근 12개월(물품+용역, 24콜)을 훑은 결과가 18,159건이었다. 1개월만 돌렸을 때가 7,954건이었으니 12개월이면 9만 건대여야 한다. 로그를 보면 창 3부터 12까지 누적 스캔이 18,159 에서 한 칸도 오르지 않았고, **실패 로그는 한 줄도 없었다.** 그 결과 56개사 중 43개사가 "공공조달 낙찰 없음 — 조달 미참여" 로 스냅샷에 적혔다
- **원인**: 조달청이 연속 요청에 **HTTP 200 · `resultMsg: 정상` · 빈 `items`** 를 돌려준다. 수집 코드는 `rows.length < PAGE_SIZE` 를 "마지막 페이지" 로 읽고 정상 종료했다. 응답 본문의 `totalCount` 는 5,777 이라고 말하고 있었는데도 그 수를 보지 않았다. 몇 분 뒤 같은 창을 같은 파라미터(`numOfRows=999`)로 다시 부르니 999행이 정상적으로 왔다 — 데이터가 없는 게 아니라 스로틀이었다
- **발견**: 커밋 직후 배치 로그의 총계가 1개월 실측치와 산술적으로 맞지 않아 창별 `totalCount` 를 직접 조회해 대조. 실패한 창들이 전부 수천 건을 갖고 있었다
- **피해**: 화면에 나가기 전에 잡았다. 나갔다면 조달 실적이 있는 기업이 "미참여" 로 표기됐을 것이다. 이 제품이 막으려는 오류(**못 본 것을 없는 것으로 적는 것**)를 제품 자신이 저지른 사례이며, `docs/2026-08-28-financial-signals.md` §4 가 "결측과 0을 구분한다" 로 경고한 바로 그 구조다. 옥타코 사고와도 같은 계열이다 — 그때는 무관한 데이터를 넣어 왜곡했고 여기서는 없는 데이터를 0으로 읽어 왜곡했다
- **재발 방지**: `scanAwards` 가 `totalCount` 를 신뢰한다 — 남은 행이 있다는데 0행이 오면 마지막 페이지가 아니라 실패다. 간격을 늘려 가며 재시도하고, 그래도 비면 `failed` 로 낸다(`src/lib/services/procurementWins.ts`). 배치는 창이 하나라도 실패하면 **"미참여" 판정을 적지 않고 `pending`("스캔 미완료")으로 남긴다**(`procurementSnapshot(summary, { complete })`). 테스트는 `src/lib/services/procurementWins.test.ts` 의 `scanAwards under throttling` 세 건. **페이지네이션이 있는 원천을 새로 붙일 때는 "행 수가 줄면 끝" 이 아니라 원천이 말한 총건수로 종료를 판정할 것**

## 2026-08-27 · 레거시 운영 리포트의 91%가 대상 기업이 주제가 아닌 기사였다 (검색 정밀도)

- **증상**: 운영 산출물 `backup/archives/media_옥타코_AI분석결과_20251112.xlsx` 는 뉴스 143건을 분석했다. 내역은 아래와 같다.

  | 구분 | 건수 | 비율 |
  |---|---|---|
  | 제목에 "옥타코" — 실제로 옥타코가 주제 | 13 | 9% |
  | 제목엔 없고 본문에만 언급 — 대표 코멘트·참여기업 나열 등 **스쳐 지나가는 언급** | 124 | 87% |
  | 제목·본문 어디에도 언급 없음 — 완전 무관 | 6 | 4% |

  **"전부 남의 회사 기사" 는 과장이다.** 91%는 옥타코가 언급되긴 하나 기사의 주제가 아니었고, 그 기사의 감성 점수가 옥타코 실적으로 집계됐다는 것이 문제다
- **원인**: 네이버 뉴스 검색은 **본문까지 매칭**한다. 레거시는 `sort=date` + `title_match or content_match` 필터(`news_service.py:508~`)를 썼는데, 네이버가 돌려주는 `description` 은 매칭 문맥이라 사실상 항상 참이 된다 — **필터가 무력화된 상태**였다. 2026-08-27 실측에서 이 필터는 약 2,000건 중 18건만 걸렀다
- **피해 정량화**: 옥타코의 감성 평균이 제목매치 기사 기준 **7.31** 인데 무관 기사 130건(평균 5.62)에 희석돼 리포트 값은 **5.78** 이 됐다. SK쉴더스 해킹(-6)·포톤 연구비 0원(-7)·다크웹 비번 유출(-8) 같은 **타사 악재가 옥타코 점수를 깎았다**. 우수기업 선정 근거로 쓰이는 수치다
- **발견**: 신규 파이프라인을 5개사로 실측하던 중 "페어리" 상위 30건이 전부 게임스컴·원신 기사인 것을 보고 레거시 산출물을 역추적
- **재발 방지**: `sort=sim` 기본(상위 30건 제목매치율 크립토랩 17→25, 올림플래닛 14→29, 페어리 1→15), `NewsItem.titleMatch` 를 관련도 신호로 기록해 정렬 우선순위에 사용, **제목매치 0건이면 `no_news` 로 종료**(논스랩은 100건 중 0건). 하드 필터로 버리지 않는 이유는 넷록스처럼 회사명이 본문에만 있는 정상 기사가 있기 때문이다. 상세는 [실행 플랜 Task 7](superpowers/plans/2026-08-26-phase0-core-loop.md), 재현은 `node scripts/news_pipeline_spike.mjs`

**교훈**: 검색 결과 건수는 품질 지표가 아니다. 1,000건을 모아도 9%만 대상 기업이면 분석은 다른 회사 이야기가 된다. 수집 단계의 정밀도가 곧 환각 방지의 첫 관문이다.

## 2026-08-26 · 훅이 jq 부재 시 조용히 통과 (fail-open)

- **증상**: 세션 중 `PATH` 가 호출마다 흔들려 `jq` 를 못 찾는 경우가 생겼고, 그때 `serviceKey=${key}` 같은 차단 대상이 검사 없이 통과했다
- **원인**: `f=$(jq ...)` 가 빈 문자열이 되고 `[ -z "$f" ] && exit 0` 로 빠졌다. 도구 부재가 "검사할 파일 없음" 과 같은 경로를 탔다
- **발견**: 훅 단위 테스트 중 exit=127 과 exit=0 이 번갈아 나오는 것을 눈으로 확인. 성공 판정에 "검사가 실제로 수행됐는가" 가 빠져 있었다 — 스모크 테스트 0건 PASS 와 같은 유형
- **재발 방지**: 세 훅 모두 첫 줄에서 `jq` 부재 시 exit 2. [`src/hooks.test.ts`](../src/hooks.test.ts) 가 `PATH=/nonexistent` 로 fail-closed 를 단정하고 `npm test` 에 수집되므로 커밋 게이트가 훅 자신을 검증한다

## 2026-08-26 · permissionDecision JSON 이 훅 차단으로 동작하지 않음

- **증상**: `{"permissionDecision":"deny"}` 를 stdout 으로 내도 도구 호출이 진행됐다
- **원인**: 현재 Claude Code 에서 범용 차단자는 **exit 2 + stderr** 다. JSON 은 사유 전달용이고, 권한 모드에 따라 무시될 수 있다
- **발견**: 커밋 `9977747` 에서 교정. 이후 OSS 조사에서 claude-code-harness 의 hookcodec 주석("Exit code 2 is the universal blocker across all hosts")으로 재확인
- **재발 방지**: 세 훅의 `deny`/`block` 이 전부 exit 2. 테스트가 exit code 를 단정하므로 JSON 방식으로 되돌리면 실패한다
