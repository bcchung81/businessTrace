# 사고 기록

같은 실수를 두 번 하지 않기 위한 로그다. **최신 항목이 위**에 온다.

이 파일은 컨텍스트에 로드되지 않는다. `CLAUDE.md` 에서 포인터로만 참조한다.

## 기록·승격 규칙

```
1회 발생  → 여기에 기록만 한다
2회 발생  → 규칙으로 승격한다
              정규식·명령으로 판정 가능 → .claude/settings.json 훅
              판단이 필요           → .claude/skills/ 스킬
CLAUDE.md → 코드 쓸 때 매번 필요한 것이 아니면 추가하지 않는다
```

한 번은 노이즈, 두 번이 패턴이다. 매 실수마다 규칙을 만들면 규칙 파일의 신호 대 잡음비가 무너진다.

항목 형식은 **증상 / 원인 / 발견 / 재발 방지** 네 줄이다. `재발 방지` 에 훅이나 스킬 링크가 없으면 그 항목은 아직 박제되지 않은 것이다.

**분리 트리거:** 이 파일이 500줄을 넘으면 연도별로 분할한다. 항목 하나가 40줄을 넘기면 그것만 별도 파일로 빼고 여기엔 요약 4줄 + 링크를 남긴다.

## 2026-08-26 · 훅이 jq 부재 시 조용히 통과 (fail-open)

- **증상**: 세션 중 `PATH` 가 호출마다 흔들려 `jq` 를 못 찾는 경우가 생겼고, 그때 `serviceKey=${key}` 같은 차단 대상이 검사 없이 통과했다
- **원인**: `f=$(jq ...)` 가 빈 문자열이 되고 `[ -z "$f" ] && exit 0` 로 빠졌다. 도구 부재가 "검사할 파일 없음" 과 같은 경로를 탔다
- **발견**: 훅 단위 테스트 중 exit=127 과 exit=0 이 번갈아 나오는 것을 눈으로 확인. 성공 판정에 "검사가 실제로 수행됐는가" 가 빠져 있었다 — 스모크 테스트 0건 PASS 와 같은 유형
- **재발 방지**: 세 훅 모두 첫 줄에서 `jq` 부재 시 exit 2. [`src/hooks.test.ts`](../src/hooks.test.ts) 가 `PATH=/nonexistent` 로 fail-closed 를 단정하고 `npm test` 에 수집되므로 커밋 게이트가 훅 자신을 검증한다

## 2026-08-26 · settings.json 의 훅 `if` 필드가 무시돼 모든 Bash 에 게이트 발화

- **증상**: `git commit` 이 아닌 일반 Bash 호출에서 `커밋 차단 — npm test 실패` 가 떴다
- **원인**: `"if": "Bash(git commit *)"` 는 settings 스키마에 없는 키다. 테스트가 늘 통과해서 매 Bash 마다 test+lint 가 돌고 있던 것을 못 봤다
- **발견**: 실패하는 테스트를 처음 추가한 직후 무관한 Bash 가 차단됨
- **재발 방지**: 스크립트가 `tool_input.command` 를 읽어 `git commit` 만 통과시킨다. 존재하지 않는 설정 키 대신 **필터 로직은 스크립트 안에 둔다**. 테스트가 비커밋 명령 exit 0 을 단정

## 2026-08-26 · permissionDecision JSON 이 훅 차단으로 동작하지 않음

- **증상**: `{"permissionDecision":"deny"}` 를 stdout 으로 내도 도구 호출이 진행됐다
- **원인**: 현재 Claude Code 에서 범용 차단자는 **exit 2 + stderr** 다. JSON 은 사유 전달용이고, 권한 모드에 따라 무시될 수 있다
- **발견**: 커밋 `9977747` 에서 교정. 이후 OSS 조사에서 claude-code-harness 의 hookcodec 주석("Exit code 2 is the universal blocker across all hosts")으로 재확인
- **재발 방지**: 세 훅의 `deny`/`block` 이 전부 exit 2. 테스트가 exit code 를 단정하므로 JSON 방식으로 되돌리면 실패한다

## 2026-08-26 · 네이버 검색 API 이관을 설정 실수로 오진

- **증상**: `Scopes are Empty` 401. 개발자센터 애플리케이션 등록 화면의 "사용 API" 목록에 검색이 없었다
- **원인**: 네이버가 검색 API 를 NAVER API HUB(네이버 클라우드)로 이관했고 2026-07-31 에 개발자센터 신규 신청이 종료됐다. 목록에 없는 것이 정상이었다
- **발견**: 뉴스·블로그·백과사전·데이터랩 4개 엔드포인트가 전부 동일하게 실패 → 개별 API 권한 문제가 아님을 확인. 이후 공식 상품 페이지에서 이관 사실 확인
- **재발 방지**: 스킬 [`external-apis`](../.claude/skills/external-apis/SKILL.md) 에 신·구 대조표. 레거시 엔드포인트 사용 시 훅이 경고

**부수 교훈**: 처음에 "위로 스크롤하면 검색이 있다"고 단정했는데 틀렸다. 화면에 없는 것을 사용자 조작 실수로 돌리기 전에 **제품 자체가 바뀌었을 가능성**을 먼저 확인한다.

## 2026-08-26 · 나라장터 경로 불일치를 미구독으로 오진

- **증상**: `NO_OPENAPI_SERVICE_ERROR` (returnReasonCode 12). 활용신청은 정상이었다
- **원인**: 서비스명 `UsrInfoService02` 의 `02` 누락. 플랜 초안에 적힌 `PubPrcrmntCorpService` 는 존재하지 않는 경로였다
- **발견**: 인증키 4조합(Decoding/Encoding × params/직접삽입)을 모두 시험해 전부 동일 에러 → 키 문제가 아님을 소거법으로 확정. 이후 경로 후보를 탐색
- **재발 방지**: 스킬 [`external-apis`](../.claude/skills/external-apis/SKILL.md) 에 에러 코드 구분표 — `NO_OPENAPI_SERVICE_ERROR` 는 경로 불일치, `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 미구독

## 2026-08-26 · data.go.kr 인증키를 URL 에 직접 삽입해 401

- **증상**: 국세청 API 가 `등록되지 않은 인증키 입니다` 401. 키는 정상 발급본이었다
- **원인**: Decoding 키를 f-string 으로 URL 에 삽입해 base64 의 `+` 가 쿼리스트링에서 공백으로 해석됐다
- **발견**: 키를 `params` 로 넘겨 라이브러리가 인코딩하도록 바꾸니 200. 이후 4조합 매트릭스로 규칙 확정
- **재발 방지**: 훅이 `serviceKey=${...}` 패턴을 차단한다. 스킬 [`external-apis`](../.claude/skills/external-apis/SKILL.md) 에 조합 매트릭스

## 2026-08-26 · 스모크 테스트가 0건 조회를 성공으로 보고

- **증상**: DART 공시 검사가 전 기업 PASS 로 나왔으나 실제로는 모두 "공시 0건 검색됨"
- **원인**: 판정이 `status == "000"` 만 보고 결과 건수를 보지 않았다. `list.json` 은 날짜 범위를 생략하면 당일 공시만 조회한다
- **발견**: PASS 인데 상세 문구가 "0건"인 모순을 눈으로 발견
- **재발 방지**: 스킬 [`external-apis`](../.claude/skills/external-apis/SKILL.md) 에 날짜 범위 필수 명시. **성공 판정에 응답 코드뿐 아니라 실제 데이터 유무를 포함한다**는 일반 원칙으로 확장
