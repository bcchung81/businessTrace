# 사용자 편의성 개선 — 설계 메모 (2026-09-02)

프로덕션(웹 컨테이너까지 완성된 현재 브랜치)을 운영자 관점에서 훑은 결과와, 그 중 무엇을 어떻게 고칠지의 결정이다. 실행 단위는 `docs/superpowers/plans/2026-09-02-usability-improvements.md` 에 있다.

## 진단 — 흐름이 막히는 곳

읽은 범위: 화면 8곳(동향·기업·기업 상세·랭킹·이력·리포트·로그인·일괄 실행)과 Route Handler 전부, 서버 액션 전부.

### 높음 — 매일 쓰는 흐름이 막힌다

| # | 문제 | 근거 |
|---|---|---|
| H1 | 기업 수정·제외 UI 가 없다 | `PATCH`/`DELETE /api/companies/[id]` 는 있으나 호출하는 화면이 없다. 별칭은 "기사 0건" 항목이 떴을 때만 편집된다 |
| H2 | 배치가 브라우저 탭에 묶여 있다 | `batch-runner.tsx` 가 언마운트 때 스트림을 끊고 서버는 `isOpen()` 으로 멈춘다. 56개사 전체 실행 동안 화면을 못 떠난다 |
| H3 | 로딩·오류·404 화면이 없다 | `src/app/` 에 `loading.tsx`·`error.tsx`·`not-found.tsx` 부재. 동향 화면은 쿼리 10여 개를 돌고 나서야 그려진다 |
| H4 | 기업명 검색이 없다 | 기업 목록·랭킹 모두 정렬·필터·20건 페이징뿐 |
| H5 | 확인 필요 조치 후 피드백이 없다 | `review-block.tsx` 가 `useTransition` 의 pending 을 버린다(`[, startTransition]`). 성공 메시지 없음, 중복 클릭 여지 |

### 중간 — 되긴 하지만 손이 많이 간다

| # | 문제 | 근거 |
|---|---|---|
| M1 | 사이드 탭이 평가연도를 잃는다 | `side-tabs.tsx` 의 href 가 `/dashboard` 등 고정. 리포트 화면은 연도 선택 자체가 없다 |
| M2 | 필터·정렬·페이지가 URL 에 없다 | 기업 목록·랭킹·사건 표가 전부 `useState`. 상세 갔다 오면 초기화 |
| M3 | 상세에 이전·다음 기업이 없고 사건 링크가 상단으로만 간다 | 상세 헤더에 "목록으로" 만. 사건 표 링크는 `/companies/{id}` |
| M4 | 동향의 "미분석 N개사 보기" 가 목록 루트로만 간다 | `/companies?year=` 로만 이동. 실행 패널은 접혀 있고 대상 미선택. `?run=…&stage=…#batch` 경로가 이미 있다 |
| M5 | 다른 탭에서 배치가 돌아도 실행 버튼이 활성이다 | 눌러야 409 를 본다 |
| M6 | 엑셀·월간 문서가 동기 생성이라 클릭 후 수 초 무반응 | `/api/reports/monthly`·`/api/companies/benchmark` 가 요청 안에서 워크북을 만든다 |

### 낮음 — 다듬기

| # | 문제 |
|---|---|
| L1 | 로그아웃 버튼이 없다 |
| L2 | 표 날짜가 월·일만이라 연도 코호트 화면에서 해가 넘어가면 애매하다 |
| L3 | 검증 근거 패널이 Esc·바깥 클릭으로 안 닫히고 포커스가 안 옮겨간다. 사건 제목은 잘린 채 `title` 툴팁뿐 |
| L4 | 용어 설명이 없다 — 열 "미확인"·"신뢰", 절 태그 "실측·분석 산출·생성형", 상세 상단 원천 요약의 빈칸 4종 |
| L5 | 등록 결과 안내가 URL 에 남아 새로고침하면 다이얼로그가 다시 열린다 |

## 결정

- **H2 는 서버 완주로 푼다.** 배치 이벤트를 프로세스 메모리(`batchRegistry`)에 버퍼링하고, 실행(POST)과 구독(GET SSE)을 분리한다. 화면은 마운트 때 진행 중이거나 방금 끝난 배치를 다시 구독한다. 중단은 별도 POST 다. 레지스트리를 DB 로 옮기는 것은 배포 Task 16 의 일이고 이 설계는 그 전 단계다 — 인터페이스(`subscribeBatch`·`publishBatchEvent`)만 지키면 저장소를 바꿔 끼울 수 있다. M5 는 이 결정으로 함께 풀린다(진행 중이면 화면이 "중단" 상태로 열린다).
- **H1 은 기업 상세 헤더의 편집 다이얼로그 하나로 푼다.** 이름·업종·사업자번호·검색 별칭·분석 대상 여부를 한 폼에 둔다. 사업자번호가 바뀌면 기존 `saveBusinessNoAction` 과 같이 원천을 바로 재조회한다. 등록 다이얼로그의 "등록된 기업" 표에는 제외·복귀 버튼만 둔다. 행 삭제는 없다 — `AnalysisRun` 이 참조한다.
- **M2 는 훅 하나로 푼다.** `useUrlState(defaults)` 가 `searchParams` 를 읽고 `router.replace(..., { scroll: false })` 로 쓴다. 표 세 개가 같은 훅을 쓴다.
- **M6 는 서버를 바꾸지 않는다.** 클라이언트 `DownloadLink` 가 fetch → Blob → 저장으로 바꾸고 그 사이 "생성 중…" 을 보인다. 워크북 생성을 비동기 작업으로 빼는 건 과하다 — 수 초 안에 끝난다.
- **L2 는 날짜 헬퍼 하나를 더한다.** `kstDateShort(iso, now)` — 같은 해면 `MM-DD`, 다른 해면 `YYYY-MM-DD`.
- **L3 의 검증 근거 패널은 shadcn Dialog 로 바꾸지 않는다.** 오른쪽 고정 패널이라는 형태는 유지하고 오버레이·Esc·포커스만 붙인다.
- 디자인 규칙은 그대로다 — 사각·그림자 없음·`signal` 변형·상태색은 판정에만. 새 색을 들이지 않는다.

## 하지 않는 것

- 공개 회원가입·권한 등급 — 관리자 전용 도구라는 전제는 그대로다.
- 스케줄러 — 배치는 사람이 누른다(기존 결정).
- 워크북 비동기 생성·파일 저장 — 위 M6 결정.
- 기업 행 삭제 — 제외(isActive=false)만.
