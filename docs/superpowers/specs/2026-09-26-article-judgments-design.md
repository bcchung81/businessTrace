# 기사 판정(06 판정) — 설계 (2026-09-26)

> claude.ai 아티팩트로 돌던 사람 정답셋 검토 페이지(`data/jev-gate/review.template.html`)를 앱의 기능으로 들인다.
> 사용자 결정(2026-09-26 Q&A): **다음 분석에 반영 + 보류 기사 자동 대기열** · 대기열 경로는 Jev 보류·LLM 회색지대·게이트 표본 83건·기업 상세 수동 ·
> **새 탭 06 판정 + 대시보드 건수** · **모델 답은 판정 전 숨김, 판정 후 공개** · **'반영 재분석' 버튼으로 모아서** 다시 분석. 나머지는 이 문서의 추천안으로 정했다.

## 목적

- 분석기(LLM·Jev)가 "이 기사가 이 회사 이야기인가"를 틀리면 사람이 한 번 가려 다음 분석부터 바로잡는다 — 누아엔터테인먼트·페어리스타 같은 동명 타사 기사
- 분석기가 확신하지 못한 기사(보류)를 사람이 가리는 대기열을 둔다
- 같은 판정이 Jev 게이트의 사람 정답셋이 된다 — 아티팩트 db·localStorage 대신 앱 DB 에 쌓인다

성공 기준: 필수 53건을 앱에서 판정하면 `scripts/eval-jev-gate.ts` 가 DB 에서 읽어 게이트를 판정한다. "주제 아님"으로 판정한 기사는 그 기업의 다음 분석에서 빠진다.

## 데이터 — `ArticleJudgment`

(companyId, link) 당 한 행. 게이트·보류·수동이 같은 기사면 같은 행을 쓴다 — 같은 기사를 두 번 판정하지 않는다.

| 필드 | 뜻 |
|---|---|
| `companyId`·`link` | 유일 키 |
| `title`·`source`·`published`·`body` | 대기열에 올린 시점의 스냅샷 — 원문이 사라져도 판정 근거가 남는다 |
| `origin` | `held`(분석기 보류) · `gate`(게이트 표본) · `manual`(기업 상세에서 올림) |
| `setKey`·`stratum`·`required` | 게이트 표본 묶음(`jev-gate-2026-09`)·층(A·B·C)·필수 여부 |
| `modelJson` | 분석기의 답(분석기·실행·주제 여부·확신도, 게이트는 Sonnet·Jev 1차 답). **판정 전에는 화면에 내지 않는다** |
| `entity`·`role`·`form` | 같은 회사인가(same·other·unclear) · 역할(main·party·many·passing) · 형식(single·roundup·market·broken) — 정답셋 분석용 기술 필드 |
| `about` | 주제 기사인가(yes·no·unsure). **null 이면 미판정**이고, 반영은 이 필드만 본다 |
| `note`·`judgedAt`·`judgedBy`·`queuedAt` | 메모와 감사 기록 |

## 반영 규칙

- `about = no` → 그 기업의 다음 분석에서 그 링크를 분석 전에 뺀다(토큰도 아낀다)
- `about = yes` → 다음 수집에 그 링크가 다시 잡히면 수집기 관련도·분석기 판정과 무관하게 주제로 넣는다. **다시 잡히지 않으면 반영할 것이 없다** — 기간 밖 기사를 끼워 넣지 않는다
- `about = unsure` → 영향 없음
- **반영 대기** = `about` 이 yes·no 인 판정 중 그 기업이 마지막으로 끝낸 분석(상태 completed·no_news — 수집만 한 실행·실패한 실행 제외)보다 늦게 내려진 것이 있는 활성 기업. 끝낸 분석이 없으면 판정이 있는 것만으로 반영 대기다. 판정 화면의 '반영 재분석' 버튼이 이 기업들만 모아 기존 웹 배치(`/api/analyze/batch`, `force`)로 다시 돌린다 — 잠금·레이트리밋·진행 표시는 배치가 이미 가진다

## 보류 규칙 — 두 분석기 공통

주제로 치지 않았는데(`!isAboutCompany`) 주제 확신도가 0.3 이상이면 보류(`held`)다 — 문턱(0.7) 아래 회색지대와, LLM 이 "N" 이라 답하고도 확신도를 높게 준 모순 답이 여기 든다. Jev 는 이미 이렇게 하고, LLM 분석기도 같은 규칙으로 `held` 를 채운다. 사람이 "주제"로 판정해 강제로 넣은 기사는 보류가 아니다.
분석이 끝나면 보류 기사 중 판정 행이 없는 것을 `origin = held` 로 대기열에 올린다. 이미 판정된 기사는 다시 올리지 않는다.

## 하지 않는 것

- 판정 즉시 재분석, 판정마다 과금 — 반영은 버튼으로 모은다
- 여러 사람의 교차 판정·합의 — 관리자 한두 명이 쓰는 도구다. 마지막 판정이 남고 `judgedBy` 로 누가 했는지 안다
- 정기 무작위 표본 — 이번 Q&A 에서 고르지 않았다
- 강제 포함 기사의 본문 주입 — 다시 수집되지 않은 기사를 스냅샷으로 끼워 넣지 않는다(분석 기간 의미가 깨진다)
