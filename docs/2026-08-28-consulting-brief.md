# 성과돋보기 구축 컨설팅 요청서

**작성일** 2026-08-28 · **대상 시스템** 성과돋보기(우수기업 선정 근거 생성·검증 시스템) · **추진 형태** 개인프로젝트

---

## 제출용 요약

> **추진배경**
> 기금사업기획팀·방송미디어팀이 제안한 AI 활용 아이디어를 실제 업무에 쓸 수 있는 형태로 구현하기 위해 프로덕션 구축에 착수했다.
> 기존 시스템은 뉴스 수집 결과를 검증 없이 집계해 분석 대상 기업과 무관한 기사가 점수에 반영되는 문제가 확인됐다.

> **프로덕션 구현 방안**
> 뉴스·공공·금융 데이터를 수집해 AI로 분석한 뒤, 그 결과를 원문·공식 출처와 자동 대조하는 4층 검증을 거쳐 평가위원회 자료를 생성한다.
> 검증을 통과하지 못한 분석은 자동 통과시키지 않고 담당자 확인 대상으로 남기며, 판단 근거와 반증 사유를 함께 제시한다.

---

## 1. 추진배경

### 1.1 제안 경위

AI 활용 아이디어 제안부서인 **기금사업기획팀**과 **방송미디어팀**의 요청에 따라, 제안 내용을 시범 수준이 아닌 실제 업무에 투입 가능한 프로덕션으로 구축하는 것을 목표로 착수했다.

### 1.2 기존 시스템의 한계 (실측 확인)

기존 Flask 기반 시스템의 운영 산출물을 역추적한 결과, 분석 품질에 구조적 문제가 확인됐다.

**분석 사례: 옥타코 리포트(2025-11-12), 뉴스 143건**

| 구분 | 건수 | 비율 |
|---|---:|---:|
| 기사 제목에 해당 기업이 등장 — 실제로 그 기업이 주제 | 13 | 9% |
| 본문에만 언급 — 대표 코멘트 인용, 참여기업 나열 등 | 124 | 87% |
| 기업 언급 자체가 없음 | 6 | 4% |

- 해당 기업이 주제인 기사만으로 계산한 감성 평균은 **7.31**이나, 무관 기사가 함께 집계돼 리포트에 실린 값은 **5.78**이었다
- 타사 보안사고 기사(−6), 다크웹 유출 기사(−8) 등이 해당 기업 점수를 끌어내렸다
- 원인은 **검증 기준의 비대칭**이었다. 수상·투자 판정에는 "해당 기업이 직접 받은 것이어야 한다"는 조건이 있었으나, 감성 분석에는 같은 조건이 없어 수집된 모든 기사가 채점 대상이 됐다

이 수치는 우수기업 선정 근거로 사용되는 값이므로, **분석 이전에 수집·검증 단계를 재설계할 필요**가 확인됐다.

### 1.3 추진 형태

기존 시스템의 재구축을 개인프로젝트로 추진하고 있으며, 현재 핵심 처리 흐름과 공공데이터 연계까지 구현을 완료한 상태다.

## 2. 추진내용

### 2.1 현재 프로덕션의 목표

**뉴스와 공공·금융 데이터를 AI로 분석해 우수기업 50개사 선정 근거를 만들고, 평가위원회에 다차원 분석자료를 제공한다.**

세부 목표는 다음 네 가지다.

| 목표 | 구현 방식 |
|---|---|
| **AI 환각 방지** (최우선) | 분석 결과를 기사 원문·공식 출처와 자동 대조하는 4층 검증. 미달 시 담당자 확인 대상으로 분류 |
| **분석 대상 정확성** | 수집 단계에서 관련도를 3등급으로 판정하고, 분석 단계에서 LLM이 "이 기사가 해당 기업에 관한 것인지"를 재확인 |
| **근거의 추적 가능성** | 모든 분석에 출처 링크를 부착하고, 근거를 찾지 못한 주장과 판단이 틀릴 수 있는 이유를 함께 제시 |
| **공식 데이터 대조** | 사업자번호를 축으로 국세청 휴폐업·DART 재무·나라장터 조달정보를 연결 |

**검증 판정 기준** — 세 항목을 모두 충족해야 '검증 완료'다.

```
근거 충실도 ≥ 0.85  그리고  출처 커버리지 ≥ 0.5  그리고  어휘 일치도 ≥ 0.4  →  검증 완료
그 외 전부 → 검토 필요 (담당자 확인)
```

조회 실패·응답 오류·판정 불가는 예외 없이 '검토 필요'로 분류한다. **검증 실패를 통과로 처리하지 않는다.**

### 2.2 프로덕션 활용 Spec

**기술 구성**

| 영역 | 채택 | 비고 |
|---|---|---|
| 애플리케이션 | Next.js 16 풀스택 (TypeScript) | 화면·API·스트리밍 단일 스택 |
| 데이터베이스 | SQLite (개발) → PostgreSQL (운영 전환 예정) | Prisma ORM |
| AI 분석·검증 | Anthropic Claude (Sonnet 5) | 분석과 검증 심사에 동일 모델 사용 |
| 본문 추출 | @mozilla/readability | 기사 본문 자동 추출 |
| 산출물 | Excel (3시트) | 종합 분석 / 뉴스별 분석 / 다차원 검증 |
| 부가 계층 | Python 사이드카 (예정) | 심층조사·재무 정규화. **장애 시에도 본 기능은 정상 동작** |

**처리 흐름**

```
기업 등록 → 뉴스 수집 → 관련도 판정 → 본문 수집 → AI 분석 → 4층 검증 → 엑셀 리포트
              (2소스)     (3등급)      (크롤링)   (기업별)    (자동)      (검증결과 포함)
```

**접근 통제** — 관리자 전용 시스템으로 공개 회원가입 경로가 없으며, 계정은 운영자가 발급한다.

**구현 진행 현황** (2026-08-28)

| 구간 | 상태 |
|---|---|
| 기반(인증·기업관리) · 핵심 흐름(수집→분석→검증→리포트) · 공공데이터 연계 | **완료** |
| 분석 실행 화면 | 미구현 (현재 API 호출로만 실행 가능) |
| 심층조사 사이드카 · 리스크 모니터링 · 벤치마킹 랭킹 · 연도별 이력 | 미구현 |

자동 테스트 253건이 통과 상태이며, 각 구간은 실제 API 호출로 결과를 확인했다.

### 2.3 외부 API 용도별 내용

| API | 용도 | 확인 결과 |
|---|---|---|
| **네이버 뉴스 검색** (API HUB) | 주 수집원. 기업별 뉴스 확보 | 정상. 관련도순 정렬 적용 시 상위 30건 중 대상 기업 기사 비율이 5개사 합계 **25%→50%** 로 개선 (올림플래닛 47%→97%, 크립토랩 57%→83%) |
| **구글 뉴스 RSS** | 보조 수집원. 네이버 미수록 기사 보완 | 정상. 원문 링크 복원 7/7 성공 |
| **언론사 사이트** (직접 수집) | 기사 본문 확보. 요약만으로는 분석·검증 불가 | 110건 중 107건 성공(97.3%) |
| **OpenDART** (금융감독원) | ①사업자번호 확보 ②재무제표(매출·영업이익·순이익·자산) | 기업 목록 118,804건 확보(24시간 캐시). **비상장 기업은 재무 미제공이 정상** |
| **국세청 휴폐업조회** | 계속사업자 여부·과세유형 확인 | 정상. 조회 실패는 '폐업'이 아니라 '미확인'으로 구분 처리 |
| **나라장터** (조달청) | 조달업체 정보(종업원수·조달업무구분·개업일) | 정상. **DART에 재무가 없는 기업도 조회되어 결측 보완에 활용 가능** |
| **Anthropic Claude** | ①뉴스 분석(동향·수상·투자) ②검증 심사 ③반증 분석 | 정상. 기업 3건 분석 기준 입력 19,132 / 출력 3,226 토큰 |

**데이터 결측에 대한 확인 사항** — 검증 대상 5개사 중 4개사는 DART 등록 자체가 없고, 1개사는 등록돼 있으나 비상장이라 재무제표가 제공되지 않는다. **재무 데이터 결측은 예외가 아니라 일반적인 상황**이며, 결측 지표를 제외하고 정규화하는 방식을 전제로 설계했다.

**재무 결측 보완 (활용신청 완료, 구현 예정)** — 비상장·비외감 기업은 재무제표가 어디에도 공개되지 않으므로, 재무제표를 대체하는 것이 아니라 **대리지표로 보완**하는 방향으로 정했다.

| 추가 API | 보완하는 지표 |
|---|---|
| 조달청 낙찰·계약정보 | 공공조달 매출 실적 — 매출 규모와 거래 지속성을 금액으로 확인 |
| 국민연금 가입 사업장 내역 | 고용 규모와 증감 추이 — 인력 유출입은 재무보다 선행하는 신호 |
| 금융위원회 기업기본정보 | 설립일·업종·종업원수. DART 미등록 기업의 커버리지 보완 |
| 중소벤처기업부 벤처기업명단 | 벤처확인 여부 — 투자·기술평가 요건 통과 여부라는 간접 신호 |

금융위원회 기업재무정보는 검토했으나 채택하지 않았다. 원천이 전자공시라 현재 겪는 결측과 동일한 범위이기 때문이다.

### 2.4 컨설팅 요청사항

**① 검증 체계의 타당성**
4층 검증 구조와 판정 임계값(0.85 / 0.5 / 0.4)이 평가위원회 근거자료로 삼기에 적절한지. 특히 종합의견에는 AI가 산출한 수치(평균 감성 점수 등)가 포함되는데 이는 기사 원문에 없는 값이라 구조적으로 '근거 없음' 판정을 받는다. 이를 결함으로 볼지, 위원회가 알아야 할 정보로 볼지에 대한 판단.

**② 데이터 수집 정확성**
관련도 3등급 판정과 공식 출처 대조 범위가 충분한지. 기업명이 일반명사와 겹치는 경우(예: 상호 "페어리")의 오탐 대응과, 비상장 기업의 재무 결측을 다른 지표로 보완하는 방식이 타당한지.

**③ 기술 아키텍처·운영**
단일 애플리케이션 + 선택적 사이드카 구조의 적정성, AI 공급자 단일 의존에 따른 위험, PostgreSQL 전환 시점, 50개사 일괄 분석 시의 처리 시간·비용 수준.

**④ 개인프로젝트 과제로서의 적절성**
현재 구현 범위와 산출물이 평가지표에 비추어 개인프로젝트 과제로 적정한 수준인지. 범위를 넓혀야 할 부분과 줄여도 되는 부분에 대한 의견.
